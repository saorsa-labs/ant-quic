## Context

Three structural limitations in `ant-quic`'s current socket and connection-endpoint architecture create compounding bandwidth, CPU, memory, and operational overhead across pure-PQC deployments (`ML-KEM-768` + `ML-DSA-65`, [ADR-003](ADR-003-pure-post-quantum-cryptography.md)):

1. **Two separate QUIC `Endpoint`s ([ADR-009](ADR-009-masque-relay-data-plane.md) Decision 3) prevent true RFC 9000 §9 in-connection migration.**
   Today `NatTraversalEndpoint` runs its primary `InnerEndpoint` over `DualStackSocket` (`src/high_level/runtime/dual_stack.rs`) and lazily spins up a **second** `shared_relay_endpoint: Arc<Mutex<Option<InnerEndpoint>>>` (`src/nat_traversal_api.rs:1814, 7864-7944`) over `MasqueRelaySocket` (`src/masque/relay_socket.rs:1746`). Because QUIC connection IDs and `Connection` state are owned by a single `Endpoint`, a relayed connection established on `shared_relay_endpoint` **cannot migrate in place** onto a physical direct UDP path:
   - [ADR-020](ADR-020-hybrid-relay-session-negotiation.md) Decision 5 (`src/p2p_endpoint.rs:7513`) must therefore open a **brand-new** direct QUIC handshake (~15 KiB pure-PQC `ML-KEM-768` + `ML-DSA-65` exchange), allocate a new `TrackedConnection.generation` / `PeerLifecycleEvent` generation, and retire the relayed connection through [ADR-017](ADR-017-single-arbiter-connection-retirement.md).
   - That generation rollover tears down active streams, bumps `saorsa-gossip`'s `AuthenticatedSession` (`ant_generation`), resets `saorsa-gossip` SG76 key caches and Wave 2 capability state, and triggers anti-entropy / catch-up bursts (the `x0x#2152` catch-up-spike class).
   - Furthermore, [ADR-020](ADR-020-hybrid-relay-session-negotiation.md) Decision 4 (`src/config/transport.rs:44`, `src/connection/paths.rs:88-100`) had to attach `virtual_path_max_udp_payload_size` at the endpoint-wide `TransportConfig` level and freeze it at `shared_relay_endpoint` creation time (leaving dynamic mid-session inner re-clamping explicitly deferred to Wave 4).

2. **Single-port `DualStackSocket` prevents single-process dual-port VPS listeners (P7).**
   `DualStackSocket` (`src/high_level/runtime/dual_stack.rs:47-61`) wraps at most one IPv4 socket and one IPv6 socket and routes outbound packets strictly by address family. `NatTraversalConfig::additional_bind_addrs` (`src/nat_traversal_api.rs:2048, 3180`) only advertises additional candidate addresses — it does not bind extra sockets or preserve per-remote source-port affinity. Consequently, downstream bootstrap/relay hosts (`x0x` ADRs `0011` and `0032`) must run **two separate `x0xd` processes with two distinct identities** per VPS (one on UDP `:443` and one on UDP `:5483`), doubling per-host gossip egress, RSS, seed-list identities, and operational surface.

3. **The active Connection ID pool (`CidQueue::LEN = 5`, `LOC_CID_COUNT = 8`) constrains ADR-015 `N = 8` paced candidate spraying.**
   `CidQueue::LEN` is currently `5` (`src/cid_queue.rs:139`), so `TransportParameters::new` (`src/transport_parameters.rs:220`) advertises `active_connection_id_limit = 5`, while `LOC_CID_COUNT` is `8` (`src/lib.rs:679`; `issue_cids_limit()` at `src/transport_parameters.rs:279`). RFC 9000 §9.5 requires each probed path to use a previously unused Destination Connection ID for path unlinkability. Today each peer only receives `min(5, 8) = 5` remote CIDs (just 4 spare CIDs after the active path), so an [ADR-015](ADR-015-paced-candidate-spray-punching.md) `N = 8` concurrent spray exhausts spare CIDs halfway through round 1. In addition, `Connection::migrate` (`src/connection/mod.rs:3801-3846`) immediately replaces `self.path` before the new path is validated — unsafe for speculative hole punching where most sprayed pairs fail.

4. **Remaining connectivity edges (mobile handoffs, IPv6-only NAT64, UDP-blocked networks).**
   Once real sockets and virtual paths live under one unified `AsyncUdpSocket`, three well-scoped follow-ons become structurally straightforward without re-architecting the transport: `draft-ietf-quic-multipath` (`PATH_STANDBY` relay failover for zero-handshake / zero-stream-loss Wi-Fi↔5G handoffs), `PREF64`/NAT64 synthesis (RFC 7050/8880/8781 for IPv6-only mobile carriers reaching IPv4-only relays), and an optional pure-PQC TLS 1.3 (`ML-KEM-768` + `ML-DSA-65`) over TCP/443 last-resort relay.

## Decision Drivers

- **100% Pure Post-Quantum Cryptography ([ADR-003](ADR-003-pure-post-quantum-cryptography.md)):** Every direct path, MASQUE tunnel, in-connection migration, and any optional TCP/443 last-resort relay MUST use `ML-KEM-768` + `ML-DSA-65` only — zero classical X25519/Ed25519 fallback or delegated classical keys.
- **Zero PQC re-handshake on relay-to-direct upgrade:** Upgrading a relayed connection to a punched direct path must preserve the live `Connection`, its streams, its `ant-quic` `PeerLifecycleEvent` / `TrackedConnection` generation, and `saorsa-gossip`'s `AuthenticatedSession` (`ant_generation`) + SG76 / Wave 2 caches.
- **Deadlock-free, acyclic relay multiplexing:** Replacing [ADR-009](ADR-009-masque-relay-data-plane.md) Decision 3's secondary endpoint must guarantee zero circular dependency and zero synchronous re-entrancy into `InnerEndpoint` when inner virtual packets traverse an outer relay session hosted on the same endpoint.
- **Non-disruptive speculative punching & RFC 9000 §9 correctness:** Probing `N = 8` direct candidates must never interrupt traffic flowing on the working MASQUE virtual path, must obey RFC 9000 §9.5 CID unlinkability and 3× anti-amplification ([ADR-015](ADR-015-paced-candidate-spray-punching.md)), must enforce single-initiator promotion (client-initiated per RFC 9000 §9) to prevent ping-pong, and must promote a direct path only after valid `PATH_RESPONSE`.
- **Single-process dual-port (`:443` + `:5483`) without spoof-hijacking:** A single VPS process with one `PeerId` must reply from the exact local port (`:443` or `:5483`) each peer dialed, even if one remote client dials both ports from the same ephemeral source port, and neither unauthenticated packets nor authenticated packets forwarded onto another port may flip send-slot affinity without RFC 9000 §8.2 path validation. Clients must remain unprivileged (never binding `<1024`).
- **Strict backwards compatibility (`<= 0.30.x`):** All new wire behaviour must be gated behind negotiated QUIC transport parameters ([ADR-012](ADR-012-standards-basis-refresh.md)); peers on `<= 0.30.x` must continue working with zero protocol break via [ADR-020](ADR-020-hybrid-relay-session-negotiation.md) Decision 5's fallback.
- **ADR-017 preservation:** [ADR-017](ADR-017-single-arbiter-connection-retirement.md) single-arbiter connection retirement must remain intact for genuine multi-connection races and legacy peers.
- **Staged delivery:** Core unified socket + in-connection migration + P7 dual-port (Phase 4A) must ship and soak independently of Multipath (Phase 4B) and NAT64/TCP-443 (Phase 4C).

## Considered Options

1. **Keep dual `InnerEndpoint`s (`DualStackSocket` + `shared_relay_endpoint`, [ADR-009](ADR-009-masque-relay-data-plane.md) Decision 3) and optimize new-handshake migration.**
   - *Rejected:* Cannot avoid the ~15 KiB pure-PQC re-handshake, cannot preserve open streams or `PeerLifecycleEvent` / `saorsa-gossip` `AuthenticatedSession` (`ant_generation`) generations across relay→direct upgrades, cannot solve single-process dual-port `:443`+`:5483` VPS consolidation, and cannot dynamically switch a connection between virtual sub-1200 MTU and physical DPLPMTUD.
2. **Unified `MultiplexedUdpSocket` using real peer `SocketAddr`s for relayed paths (reusing ADR-020's address stamping).**
   - *Rejected:* Stamping relayed packets with the target peer's real `SocketAddr` collides inside a single `Endpoint` with direct candidate probes to that same `SocketAddr` (the exact collision observed in [ADR-020](ADR-020-hybrid-relay-session-negotiation.md) Context). Quinn's `Connection` path state cannot distinguish a relayed path from a direct path if both carry the identical `SocketAddr`.
3. **Key multi-port (`:443` / `:5483`) source-socket affinity strictly on `remote_addr` inside `AsyncUdpSocket`.**
   - *Rejected as sole mechanism:* Vulnerable to (a) collision when a single client dials both `:443` and `:5483` from the same ephemeral source port, and (b) source-port affinity hijacking if an unauthenticated attacker spoofs a UDP packet with a victim's `remote_addr` toward the secondary port.
4. **Unified `MultiplexedUdpSocket` with validated `(remote_addr, local_slot)` path identity, acyclic physical-slot pinning for outer relay connections, disjoint synthetic ULA virtual-path addressing (`fd00:53a0:5251::/48`), per-path virtual MTU, `CidQueue::LEN = LOC_CID_COUNT = 16`, and negotiated client-initiated RFC 9000 §9 migration (Chosen).**
   - *Chosen:* Solves all three architectural gaps in one coherent substrate, directly answers [ADR-009](ADR-009-masque-relay-data-plane.md) Decision 3's circular-dependency concern, preserves `quinn_udp` GSO/GRO/ECN, [ADR-017](ADR-017-single-arbiter-connection-retirement.md), [ADR-020](ADR-020-hybrid-relay-session-negotiation.md) `DatagramMuxV1`, and `<= 0.30.x` backwards compatibility, and cleanly stages Multipath and NAT64/TCP-443 as Phase 4B/4C follow-ons.

## Decision

We will adopt a three-phase architecture centered on a single unified `MultiplexedUdpSocket` per `P2pEndpoint` (**Phase 4A**), followed by **Phase 4B** (QUIC Multipath `PATH_STANDBY`) and **Phase 4C** (`PREF64`/NAT64 synthesis and optional pure-PQC TCP/443 last-resort relay). Each phase keeps its behaviour-changing triggers opt-in (Phase 4A: `auto_migrate = false` per [ADR-020](ADR-020-hybrid-relay-session-negotiation.md) Decision 6 and explicit multi-port bind-slot opt-in, while wire capability negotiation `InConnectionMigrationV1 (0x50C6)` is enabled by default so upgraded peers can negotiate cleanly) and clears its own soak gate before any default flip.

### Phase 4A — Unified `MultiplexedUdpSocket`, P7 Dual-Port, and True In-Connection Migration

#### 1. Single `InnerEndpoint` over `MultiplexedUdpSocket: AsyncUdpSocket` (Supersedes ADR-009 Decision 3 & ADR-016 Secondary-Endpoint Clause)

Replace `DualStackSocket` (`src/high_level/runtime/dual_stack.rs`) and the separate `shared_relay_endpoint` (`src/nat_traversal_api.rs:1814, 7864-7944`) + `MasqueRelaySocket` (`src/masque/relay_socket.rs:1746`) with a single `MultiplexedUdpSocket` implementing `AsyncUdpSocket` (`src/high_level/runtime.rs:49`) for the node's sole `InnerEndpoint`:

- **Answering [ADR-009](ADR-009-masque-relay-data-plane.md) Decision 3's circular-dependency argument (strict 2-level DAG + non-re-entrant async boundary):**
  - ADR-009 Decision 3 created a secondary Quinn endpoint because rebinding the single main endpoint directly onto `MasqueRelaySocket` would sever/tunnel the outer relay control connection through itself. `MultiplexedUdpSocket` eliminates that circular dependency by keeping **physical UDP slots** (`SocketSlotId(0..MAX_PHYSICAL_SLOTS)`) and **virtual relay routes** (`SocketSlotId::VIRTUAL`) disjoint inside one `AsyncUdpSocket` under two hard invariants:
    1. **Outer relay connections pinned strictly to physical slots (strict 2-level acyclic DAG):** Every outer QUIC connection hosting a MASQUE relay session (`NatTraversalEndpoint::relay_sessions`, `src/nat_traversal_api.rs:1803`) MUST be opened on and pinned strictly to a physical `SocketSlotId` — it MUST NEVER target a synthetic virtual address, MUST NEVER be bound to `SocketSlotId::VIRTUAL`, and MUST NEVER migrate onto a virtual route (enforced at dial time and inside `Connection` migration admission). Packet flow is therefore a strict 2-level DAG: `inner virtual Connection -> virtual egress channel -> outer physical relay Connection -> physical UDP socket`, making recursive tunneling impossible.
    2. **Non-re-entrant, deadlock-free send/recv boundary:** When `InnerEndpoint` calls `MultiplexedUdpSocket::send()` for a `Transmit` targeting a virtual route, `send()` NEVER synchronously re-enters `InnerEndpoint`, NEVER acquires any `Endpoint` lock, and NEVER blocks `poll_send` on outer QUIC stream/datagram flow control. Instead, `send()` performs a non-blocking `try_send` into a bounded per-relay egress `mpsc` channel (dropping on full to preserve UDP loss semantics so inner congestion control observes real pressure and `InnerEndpoint` never deadlocks). Symmetrically on ingress, an independent Tokio relay ingress task reads packets from the outer `Connection` and enqueues them into `MultiplexedUdpSocket`'s bounded virtual receive queue via non-blocking **drop-on-full** (counted as `virtual_recv_queue_dropped`, matching UDP socket receive-buffer overflow semantics so a slow consumer never backpressures the outer relay pump or starves sibling virtual routes/control capsules), waking `poll_recv` via its stored `Waker`. An independent Tokio relay egress task drains the egress channel onto the outer physical `Connection` (datagram lane via `DatagramMux` or stream lane for Initials/oversize).
- **Physical socket groups (`SocketSlotId(u8)`, up to `MAX_PHYSICAL_SLOTS = 4`):**
  - Slot `0` is the primary dual-stack pair `(Option<UdpSocket v4>, Option<UdpSocket v6>)` with paired `quinn_udp::UdpSocketState`s (preserving kernel `recvmmsg`, `UDP_GRO`, `UDP_GSO`, `DF`, and ECN on both families, identical to today's `DualStackSocket`).
  - Additional bind ports (e.g. VPS listening on both `:443` in slot `0` and `:5483` in slot `1`, configured via an explicit opt-in multi-bind config surface — keeping `NatTraversalConfig::additional_bind_addrs` backward-compatible without breaking clients, which default to 1 unprivileged ephemeral slot) each allocate a `SocketSlotId` with their own `(v4, v6, UdpSocketState)`.
  - `AsyncUdpSocket::local_addrs()` returns every bound physical `SocketAddr` across all slots so shutdown and diagnostics inspect all descriptors cleanly.
- **Validated `(remote_addr, local_slot)` path identity & spoof-resistant affinity (delivering P7 single-process dual-port):**
  - Thread a 1-byte `local_slot: SocketSlotId` alongside `RecvMeta` / `Transmit` inside `ant-quic`'s internal `Endpoint` ↔ `Connection` ↔ `PathData` path:
    1. `MultiplexedUdpSocket::poll_recv` tags every received datagram with the `SocketSlotId` of the physical socket that received it (or `SocketSlotId::VIRTUAL` for virtual MASQUE routes).
    2. **Path identity invariant:** A validated path's identity is the tuple **`(remote_addr, local_slot)`** (not `remote_addr` alone). `Connection` records `local_slot` on `PathData` (`src/connection/paths.rs:23`) **at path creation (the first incoming Initial packet or outbound dial, before any handshake reply is transmitted)** and propagates `self.path.local_slot` (or a probe's `local_slot`) onto every outbound `Transmit` from packet #1 onward.
    3. **Slot-mismatch anti-hijack rule:** If a packet — **even an authenticated 1-RTT packet with a valid DCID and AEAD tag** (e.g. forwarded/replayed by an on-path attacker or NAT from `:443` onto `:5483`) — arrives with `recv_meta.local_slot != self.path.local_slot`, `Connection::handle_packet` MUST NOT flip `self.path.local_slot` immediately. It treats `(remote_addr, recv_meta.local_slot)` as an **unvalidated path change** under RFC 9000 §8.2: active traffic stays on `self.path.local_slot` until RFC 9000 §8.2 `PATH_CHALLENGE` / `PATH_RESPONSE` succeeds on the exact `(remote_addr, recv_meta.local_slot)` tuple (subject to RFC 9000 §8.1 3× anti-amplification on that slot).
    4. `MultiplexedUdpSocket::send` routes every established connection packet strictly via `Transmit.local_slot`, never consulting a spoofable IP-only map.
    5. For stateless replies that have no `Connection` state (`Retry`, `VersionNegotiation`, stateless reset), the stateless reply path echoes the triggering packet's `RecvMeta.local_slot` directly (zero persistent state, zero spoof-hijacking, zero collision even when one remote client dials both `:443` and `:5483` from the exact same ephemeral port).
    6. Outbound dials default to `SocketSlotId(0)` (e.g. `:443` on dual-port VPS, ephemeral high port on clients — preserving `x0x/ADR-0011` Decision 2 that clients never bind privileged ports).
- **Disjoint process-internal synthetic ULA virtual-path address space (`fd00:53a0:5251::/48`):**
  - Every active virtual MASQUE route `(relay_slot: u16, target_addr: SocketAddr)` is assigned a unique synthetic IPv6 `SocketAddr` inside the **process-internal reserved Unique Local Address (ULA, RFC 4193) prefix `fd00:53a0:5251::/48`**:
    ```text
    [ 48 bits: fd00:53a0:5251 ][ 16 bits: relay_slot ][ 32 bits: route_gen ][ 32 bits: target_idx ]
    port: target_addr.port().max(1)
    ```
    *(Note on RFC 4193 §3.2.2: ULA addresses are site-local rather than globally routable, and RFC 4193 specifies locally generated random 40-bit Global IDs rather than a fixed constant. The fixed Global ID `00:53a0:5251` is used here strictly as a **process-internal** discriminator for deterministic diagnostics and MUST NEVER leave the local process on any socket or protocol frame; an implementing PR may alternatively generate a per-endpoint random RFC 4193 `/48` via `OsRng` behind a shared `is_synthetic_virtual_ip` predicate if local site-ULA collision risk is ever encountered.)*
  - **Hard isolation & intake/emission filtering invariant (`is_synthetic_virtual_ip`):** The synthetic virtual prefix MUST be rejected at **every** external boundary — both wire/socket and candidate/address intake/emission:
    1. Physical socket `send()` MUST reject any destination matching `is_synthetic_virtual_ip` with `io::ErrorKind::InvalidInput`.
    2. Physical socket `poll_recv()` MUST drop any packet whose source IP matches `is_synthetic_virtual_ip` (counted as `synthetic_prefix_spoof_dropped`) so a LAN/site peer can never inject frames into the virtual-path address space.
    3. QUIC NAT-traversal frames — **`ADD_ADDRESS`**, **`OBSERVED_ADDRESS`**, and **`PUNCH_ME_NOW`** — MUST reject/ignore any address matching `is_synthetic_virtual_ip` on **intake**, and MUST NEVER emit any address matching `is_synthetic_virtual_ip` on **egress** (`queue_observed_address_frame` and candidate advertisement skip synthetic paths).
    4. Candidate discovery & address stores — **`CandidateDiscoveryManager`**, **`BootstrapCache`**, **`PeerHintRecord`**, **`manual_known_peer_udp_addrs`**, OS interface enumeration, and mDNS — MUST filter out any address matching `is_synthetic_virtual_ip` before insertion or persistence.
  - The virtual route table is hard-capped at `MAX_VIRTUAL_ROUTES = 4096` (bounded per-relay and globally per [ADR-014](ADR-014-relay-resource-governance.md)) with monotonic `route_gen` preventing route aliasing across relay reconnects.
  - Because `MultiplexedUdpSocket::local_addr()` returns an IPv6 address whenever any IPv6 socket or virtual route is enabled, Quinn normalizes IPv4 peers to `::ffff:a.b.c.d` while virtual MASQUE paths carry the disjoint synthetic ULA prefix — guaranteeing 100% disjointness between a peer's relayed path and every direct IPv4/IPv6 candidate address.
  - Existing [ADR-020](ADR-020-hybrid-relay-session-negotiation.md) MASQUE data-plane mechanics (`DatagramMuxV1 (0x50C4)`, `COMPRESSION_ASSIGN`, 4-context `draft-seemann-masque-connect-udp-ecn-01` ECN mapping, `UDP_GRO` stride splitting, `900 B` `P_max` floor, stream-lane routing for Initials and 1,200 B `PATH_CHALLENGE`s) run unchanged beneath the virtual-route driver in `MultiplexedUdpSocket`.
- **Fair receive scheduling:**
  - `MultiplexedUdpSocket::poll_recv` rotates across all active physical slots and virtual MASQUE receive queues via an atomic cursor (`poll_cursor: AtomicUsize`) with a bounded per-source burst limit so neither physical floods nor relay traffic can starve the other.

#### 2. Dynamic Per-Path Virtual MTU Clamp (Replaces Proposed ADR-020 Decision 4 Static Clamp)

- Move the virtual-path sub-1200 MTU floor exemption from endpoint-wide `TransportConfig::virtual_path_max_udp_payload_size` (`src/config/transport.rs:44`) to **per-path `PathData`** (`src/connection/paths.rs:23`):
  - `AsyncUdpSocket` gains a default method `fn virtual_path_mtu(&self, _remote: SocketAddr) -> Option<u16> { None }`, overridden by `MultiplexedUdpSocket` to return `compute_inner_virtual_path_mtu(outer_conn.max_datagram_size(), active_overhead)` (floor `MIN_VIRTUAL_PATH_MTU = 900`, cap `1380`) when `remote` matches `is_synthetic_virtual_ip`, and `None` for physical addresses.
  - When `PathData` targets a virtual address (`Some(vp_mtu)`): inner Initials keep RFC 9000 §14.1 `1200 B` padding (routed on the MASQUE stream lane), post-handshake 1-RTT packets clamp to `vp_mtu`, inner DPLPMTUD locks at `vp_mtu`, and 1,200 B `PATH_CHALLENGE`/`PATH_RESPONSE` frames ride the stream lane when `1200 > P_max`.
  - **Dynamic mid-session outer-MTU shrink:** When the outer MASQUE connection's `max_datagram_size()` shrinks mid-session (e.g. outer DPLPMTUD blackhole detection), `MultiplexedUdpSocket` updates a shared `AtomicU16` per `relay_slot` read by `PathData` on transmit (or notifies active connections on that `relay_slot`), immediately lowering the virtual path's 1-RTT ceiling and invoking `drop_oversized_datagrams` (`src/connection/mod.rs:3838`) — closing the exact deferral noted in [ADR-020](ADR-020-hybrid-relay-session-negotiation.md) Decision 4.
  - When the connection migrates in place to a **physical** direct path (`virtual_path_mtu(remote) == None`): `PathData::new` automatically uses standard `INITIAL_MTU = 1200` and enables full physical DPLPMTUD up to `1,452 B`.

#### 3. CID Pool Expansion (`CidQueue::LEN = LOC_CID_COUNT = 16`)

- Raise `CidQueue::LEN` (`src/cid_queue.rs:139`) from `5` to `16` and `LOC_CID_COUNT` (`src/lib.rs:679`) from `8` to `16`:
  - `TransportParameters::new` (`src/transport_parameters.rs:220`) advertises `active_connection_id_limit = 16` when CID length > 0.
  - **Both CID directions explicitly:**
    - **Outbound probe budget (CIDs received from the remote peer into our `rem_cids`):** bounded by `min(our active_connection_id_limit, peer's LOC_CID_COUNT)`. Against a Wave-4 peer (`LOC_CID_COUNT = 16`), we receive `min(16, 16) = 16` CIDs (1 active + `N = 8` concurrent [ADR-015](ADR-015-paced-candidate-spray-punching.md) probes + 2 standby/migration slots + 5 retirement headroom). Against a `<= 0.30.x` peer (`LOC_CID_COUNT = 8`), we receive `min(16, 8) = 8` CIDs (7 spare).
    - **CIDs we issue to the remote peer (`TransportParameters::issue_cids_limit()` at `src/transport_parameters.rs:279`):** `min(peer.active_connection_id_limit, our LOC_CID_COUNT = 16)`. Against a Wave-4 peer we issue `16`; against a `<= 0.30.x` peer (`active_connection_id_limit = 5`) we issue `5` with zero wire break.
    - Each outbound probe round dynamically caps its concurrent probe width to `min(MAX_CONCURRENT_PROBE_PATHS, rem_cids.spare_count())` so a peer issuing fewer than 9 CIDs never stalls probing or reuses an active DCID.
  - **0-RTT forward/rollback semantics:** `TransportParameters::validate_resumption_from` (`src/transport_parameters.rs:254-272`, invoked at `src/connection/mod.rs:3244`) checks `cached.active_connection_id_limit > self.active_connection_id_limit` and returns `Err(TransportError::PROTOCOL_VIOLATION("0-RTT accepted with incompatible transport parameters"))`. Therefore:
    - Upgrading a server `5 -> 16` satisfies `5 <= 16` and preserves 0-RTT resumption cleanly.
    - Rolling back a server `16 -> 5`: in pinned `rustls 0.23`, server-side early-data admission performs **no** comparison of QUIC transport parameters embedded in resumption tickets (`QuicServerConfig` at `src/crypto/rustls.rs:549` only sets `max_early_data_size = u32::MAX`). Consequently, after an unmitigated `16 -> 5` server rollback, the server can accept a pre-rollback 0-RTT ticket and the client will close the connection with `TransportError::PROTOCOL_VIOLATION` (`src/connection/mod.rs:3244`) until old tickets expire. **Required rollback procedure:** any `16 -> 5` server downgrade MUST disable early data (`max_early_data_size = 0`) or rotate/flush the server's TLS session ticket key / session cache for one ticket lifetime so pre-rollback tickets are rejected at TLS and clients fall back cleanly to 1-RTT. Clients observing a resumption error or downgrade discard stale 0-RTT tickets.
  - **CID replenishment invariant:** As soon as a probe pair fails or is cancelled upon first `PATH_RESPONSE`, the connection emits `RETIRE_CONNECTION_ID` for unused probe CIDs so the peer replenishes the 16-CID pool ahead of any future migration round.

#### 4. Negotiated Non-Disruptive In-Connection Relay-to-Direct Migration (`InConnectionMigrationV1`)

- **Wire negotiation ([ADR-012](ADR-012-standards-basis-refresh.md) compliance):**
  - Define a new zero-length QUIC transport parameter **`InConnectionMigrationV1` (`0x50C6`)** following ant-quic's even-stride private range (`PqcAlgorithms = 0x50C0`, `AckReceiveV2 = 0x50C2`, `DatagramMuxV1 = 0x50C4` in `src/transport_parameters.rs:1163-1167`), enabled by default via `TransportConfig::in_connection_migration_v1(true)` and validated in `TransportParameters::validate_resumption_from` (symmetric with `datagram_mux_v1`: any mismatch rejects 0-RTT with `PROTOCOL_VIOLATION`).
  - Author/update `docs/rfcs/ant-quic-nat-traversal.md` (currently absent per [ADR-012](ADR-012-standards-basis-refresh.md) Decision 1) as our normative specification in the implementing PR (citing expired `draft-seemann-quic-nat-traversal-02` §4.4.1 as provenance only).
- **Non-disruptive speculative probing, asymmetric initiator role, & atomic promotion (replacing destructive pre-validation `migrate()`):**
  - Add a bounded `probing_paths` table on `Connection` (hard-capped at `MAX_CONCURRENT_PROBE_PATHS = 8` matching [ADR-015](ADR-015-paced-candidate-spray-punching.md)) separate from `self.path`:
    1. **Symmetric pinhole probing:** While active traffic continues uninterrupted over `self.path` (the synthetic MASQUE virtual path), `PUNCH_ME_NOW`-coordinated rounds allow both endpoints to spray up to `min(MAX_CONCURRENT_PROBE_PATHS, rem_cids.spare_count())` `PATH_CHALLENGE` probes (padded to `1,200 B`, paced at `>= max(20 ms, min_rtt/10)`, bounded by RFC 9000 §8.1 3× anti-amplification) to direct physical candidates, each using a distinct unused remote CID from `rem_cids` (RFC 9000 §9.5) and a fresh 64-bit challenge token. Incoming `PATH_RESPONSE` frames are matched by token against `probing_paths` (surviving NAT port rebinding per [ADR-015](ADR-015-paced-candidate-spray-punching.md) Decision 3), and valid incoming `PATH_CHALLENGE`s are answered with `PATH_RESPONSE` on the exact receiving `(remote_addr, local_slot)`.
    2. **Asymmetric migration initiator role & `0x50C6` server-address-change authorization (RFC 9000 §9.6 / §9.3, zero ping-pong):**
       - From the client's perspective, migrating from a MASQUE relay path to a direct physical path is a **change of server address**, which base RFC 9000 permits only via static `preferred_address` (RFC 9000 §9.6). Here, **mutually negotiated `InConnectionMigrationV1` (`0x50C6`)** — with `server_config.migration == true` (`src/connection/mod.rs:6218`, i.e., server has not set `disable_active_migration`) — is the explicit QUIC transport extension authorizing a client-initiated move to a validated direct server address (citing expired `draft-seemann-quic-nat-traversal-02` §4.4.1 as provenance; normative rules specified in `docs/rfcs/ant-quic-nat-traversal.md` per [ADR-012](ADR-012-standards-basis-refresh.md)).
       - **Scoped relaxation of `Connection::handle_event` (`src/connection/mod.rs:1623`):** Today `src/connection/mod.rs:1623` drops any packet where `remote != self.path.remote && !self.side.remote_may_migrate()` **before decryption**, and `remote_may_migrate()` (`src/connection/mod.rs:6216`) is unconditionally `false` on `ConnectionSide::Client`. Under `InConnectionMigrationV1 (0x50C6)` ONLY, that pre-decryption drop is deferred to **after AEAD decryption/authentication** (`handle_decode`), where off-path packets on `Side::Client` are admitted strictly if they authenticate (valid DCID + AEAD) AND either (a) arrive from an `(remote, local_slot)` already tracked in `probing_paths` carrying probing frames (`PATH_RESPONSE` / `PATH_CHALLENGE`) or (b) carry an authenticated `PATH_CHALLENGE` that seeds a new bounded probe entry in `probing_paths` (capped at `MAX_CONCURRENT_PROBE_PATHS`, subject to RFC 9000 §8.1 3× anti-amplification). Packets failing decryption, non-probing packets from unvalidated addresses on `Side::Client`, and ALL off-path packets when `0x50C6` was not negotiated or `server_config.migration == false` remain dropped immediately.
       - **Only the QUIC client (`Side::Client`) actively initiates connection migration:**
         - On **`Side::Client`**: upon receiving the **first valid `PATH_RESPONSE`** on a physical direct candidate, the client cancels remaining probes in the round (retiring their unused probe CIDs), atomically promotes that already-validated `(remote_addr, local_slot)` `PathData` into `self.path` (with `validated = true`, physical `MtuDiscovery::new(...)`, and the probe's DCID), and begins transmitting non-probing 1-RTT frames on that direct path.
         - On **`Side::Server`**: when the server receives a `PATH_RESPONSE` to its own direct probe, it marks that candidate pair validated in `probing_paths` **without** switching `self.path` (preventing both-sides-promote ping-pong). When the client's first non-probing 1-RTT packet arrives on that validated `(remote_addr, local_slot)` (RFC 9000 §9.3 responding to peer migration), the server atomically promotes `self.path` to that exact `(remote_addr, local_slot)` and cancels remaining probes. If the client did not yet know the server's direct address, the server's authenticated `PATH_CHALLENGE` (admitted under the scoped `0x50C6` line-1623 relaxation above) seeds that `(remote_addr, local_slot)` in the client's `probing_paths` so the client immediately validates and initiates migration.
    3. **Graceful drain & blackhole rollback:** On promotion, the old virtual MASQUE path moves into `self.prev_path` for a `3 * max(pto, prev_pto)` drain grace so any in-flight relayed packets still arrive and are acknowledged cleanly; if the promoted direct path immediately blackholes before completing its first 1-RTT ACK, `Connection` falls back cleanly to `prev_path` without dropping the session.
    4. **Upper-layer `PathMigrated` state rewrite (zero generation rollover):** `Connection` emits `PathMigrated { peer_id, old_remote, new_remote, via_relay: false }` to `P2pEndpoint`, which updates path metadata in place **without replacing the `Connection` handle, without emitting `PeerLifecycleEvent::Replaced` or bumping `TrackedConnection.generation` / `saorsa-gossip` `AuthenticatedSession` (`ant_generation`), without invoking [ADR-017](ADR-017-single-arbiter-connection-retirement.md) connection retirement, and without resetting `saorsa-gossip` SG76 key caches or Wave 2 capabilities.** Specifically, `PathMigrated` rewrites:
       - `P2pEndpoint::connected_peers` (`src/p2p_endpoint.rs:1676, 1919-1927`): `PeerConnection.remote_addr` → `TransportAddr::Udp(new_remote)` and `PeerConnection.traversal_method` → `HolePunched` / `Direct`;
       - `P2pEndpoint::direct_path_statuses` (`src/p2p_endpoint.rs:1758`): marks the peer's direct path active at `new_remote`;
       - `NatTraversalEndpoint::connection_lifecycle` (`src/nat_traversal_api.rs:424, 1756`): updates the live `TrackedConnection.traversal_method` in place (same `generation`);
       - `NatTraversalEndpoint::successful_candidates` (`src/nat_traversal_api.rs:1842`): records `peer_id -> new_remote`;
       - `NatTraversalEndpoint::relay_advertised_peers` (`src/nat_traversal_api.rs:1859`): prunes/updates the migrated `old_remote` entry if present;
       - `P2pEndpoint::bootstrap_cache` (`src/p2p_endpoint.rs:1706`): records reachability for the physical `new_remote` (never persisting any synthetic ULA virtual address);
       - `P2pEndpoint::stats` and `migration_stats` (`src/p2p_endpoint.rs:1679, 1685`): updates direct/relayed gauges and in-connection migration counters.
       - `NatTraversalEndpoint::relay_sessions` (`src/nat_traversal_api.rs:1803`, keyed by the *relay server's* physical `SocketAddr`) is untouched; the inner virtual route entry in `MultiplexedUdpSocket` is reclaimed once the `3 * max(pto, prev_pto)` drain grace completes.
    5. **Compatibility fallback (`<= 0.30.x`):** When either end did not negotiate `InConnectionMigrationV1 (0x50C6)` (or the server advertised RFC 9000 `disable_active_migration`, or `rem_cids.spare_count() == 0`), `P2pEndpoint` automatically uses [ADR-020](ADR-020-hybrid-relay-session-negotiation.md) Decision 5's verified new-handshake migration + [ADR-017](ADR-017-single-arbiter-connection-retirement.md) retirement.
  - **`auto_migrate` rollout gate:** `auto_migrate` remains `false` by default until the Wave 4 connection-lifecycle soak passes (matching [ADR-020](ADR-020-hybrid-relay-session-negotiation.md) Decision 6).

### Phase 4B — QUIC Multipath (`PATH_STANDBY` Relay Failover)

Deferred to a follow-on PR after Phase 4A soaks cleanly:

- Adopt `draft-ietf-quic-multipath` (active IETF QUIC WG draft; negotiated via `initial_max_path_id` transport parameter, keeping wire codepoints frozen behind negotiation per [ADR-012](ADR-012-standards-basis-refresh.md)).
- Instead of closing the MASQUE virtual path after 3× PTO drain grace, retain it as a **`PATH_STANDBY`** path (`path_id = 0` or dedicated standby ID) with low-frequency keepalive while the direct physical path carries 100% of application data.
- On Wi-Fi↔5G handoff or sudden NAT mapping expiry (detected via PTO loss on the direct path), the scheduler immediately fails traffic over to the already-validated `PATH_STANDBY` relay path with **zero handshake and zero stream loss** while triggering a fresh non-disruptive punch for the new interface.
- **Relay governance ([ADR-014](ADR-014-relay-resource-governance.md)):** Standby MASQUE contexts must carry an idle eviction TTL (e.g. 120 s configurable) and separate quota accounting so idle standby paths cannot starve active relayed clients on VPS relays.

### Phase 4C — `PREF64`/NAT64 Synthesis & Optional Pure-PQC TCP/443 Last-Resort Relay

Deferred to independent follow-on PRs after Phase 4A:

- **`PREF64` / NAT64 synthesis (RFC 7050 / RFC 8880 / RFC 8781):**
  - When a host has IPv6-only connectivity (no default IPv4 route, common on mobile carriers) and needs to reach an IPv4-only bootstrap/relay address, discover the local NAT64 prefix via OS Router Advertisement `PREF64` (RFC 8781, where available) with RFC 7050 `ipv4only.arpa` DNS64 fallback (bounded timeout, cached per interface fingerprint alongside Happy Eyeballs v3 — `draft-ietf-happy-happyeyeballs-v3` — health state from `#374` Part B2).
  - Synthesize RFC 6052 IPv6 addresses (`nat64_prefix || ipv4`) for IPv4-only targets and feed them into the normal Happy Eyeballs v3 (`draft-ietf-happy-happyeyeballs-v3`) dialer. Never synthesize for hosts that already have native IPv4 or native IPv6 reachability to that peer.
- **Optional pure-PQC TLS 1.3 over TCP/443 last-resort relay:**
  - Strictly **opt-in** and **last-resort only** (attempted only after direct UDP, UDP/443 MASQUE, and UDP/5483 MASQUE all fail — targeting UDP-blocked corporate/hotel networks and sub-900 B MTU tunnels).
  - Must use **pure-PQC TLS 1.3 (`ML-KEM-768` + `ML-DSA-65` RPK, zero classical fallback)** per [ADR-003](ADR-003-pure-post-quantum-cryptography.md), carrying length-prefixed QUIC datagrams as a virtual route inside `MultiplexedUdpSocket` (identical process-internal synthetic ULA abstraction, still obeying the strict 2-level DAG and non-re-entrant async channel boundary).
  - Requires its own focused security/DoS review (TCP socket exhaustion, Slowloris/half-open caps, explicit VPS opt-in) before shipping.

## Consequences

### Positive

- **Zero PQC re-handshake on relay→direct upgrades:** Eliminates ~15 KiB ML-KEM-768/ML-DSA-65 handshakes, stream teardowns, `PeerLifecycleEvent::Replaced` / `saorsa-gossip` `AuthenticatedSession` (`ant_generation`) rollovers, [ADR-017](ADR-017-single-arbiter-connection-retirement.md) supersede cycles, and `saorsa-gossip` SG76/Wave-2 session resets during NAT traversal upgrades.
- **Single-process dual-port VPS consolidation (P7):** Enables downstream `x0x` bootstrap/relay hosts to bind both `:443` and `:5483` (IPv4 + IPv6) inside ONE process with ONE `PeerId`, cutting per-host gossip egress and RSS in half and retiring the operational complexity of dual `x0xd` + `x0xd-443` services (`x0x` ADRs `0011` and `0032`).
- **Dynamic virtual-path MTU safety:** Closes [ADR-020](ADR-020-hybrid-relay-session-negotiation.md)'s mid-session outer-MTU shrink deferral and automatically unlocks full physical DPLPMTUD (`1,200 -> 1,452 B`) the instant a connection migrates off a sub-1200 virtual MASQUE path onto a direct path.
- **Unblocked ADR-015 `N = 8` spray with RFC 9000 §9.5 unlinkability:** `CidQueue::LEN = LOC_CID_COUNT = 16` gives every concurrent spray probe its own fresh unused DCID without mid-round CID starvation.
- **Clean foundation for Multipath & NAT64:** `MultiplexedUdpSocket`'s unified virtual+physical path model makes `PATH_STANDBY` and NAT64 synthesis additive rather than disruptive rewrites.

### Negative / Trade-offs

- **Increased internal state complexity in `Connection` and `AsyncUdpSocket`:** Threading `local_slot` across `RecvMeta`/`Transmit`/`PathData`, enforcing validated `(remote_addr, local_slot)` path identity, managing `probing_paths` alongside `self.path`/`prev_path`, and maintaining the process-internal synthetic ULA virtual route table add carefully audited state-machine surface to `ant-quic`'s core transport loop.
- **Small per-connection memory increase:** Raising `CidQueue::LEN` from `5` to `16` adds ~440 B per live `Connection` (plus ~1 KiB transient state during active `N = 8` probing), negligible relative to a single ~15 KiB PQC handshake.
- **Mixed-fleet dual path during rollout:** Until the fleet upgrades past the Wave 4 release, `P2pEndpoint` must maintain both the new `InConnectionMigrationV1 (0x50C6)` path and the [ADR-020](ADR-020-hybrid-relay-session-negotiation.md) Decision 5 new-handshake fallback for `<= 0.30.x` peers.
- **Privileged bind still required on VPS `:443`:** Single-process dual-port removes the *second* process, not OS permission (`CAP_NET_BIND_SERVICE`) on the VPS; clients continue binding only unprivileged ephemeral ports.

### Neutral / Operational

- **New wire parameter:** One zero-length QUIC transport parameter `InConnectionMigrationV1 (0x50C6)` + increased RFC 9000 `active_connection_id_limit` (`5 -> 16`, standard parameter `0x0e`). Zero breaking change for `<= 0.30.x` peers.
- **Downstream `x0x` P7 rollout:** Once `ant-quic` ships Phase 4A, `x0x` can retire `x0xd-443.service` via a separate `x0x` ADR/rollout plan configuring both `:443` and `:5483` bind slots on the primary `x0xd` instance (preserving single `machine.key` identity per host).
- **ADR-017 interaction:** [ADR-017](ADR-017-single-arbiter-connection-retirement.md) remains unmodified and authoritative whenever two distinct connections genuinely coexist (simultaneous open, reconnect, or `<= 0.30.x` fallback).

## Validation

Phase 4A implementation PRs MUST ship with the following unit, integration, and soak gates before `auto_migrate` or single-process dual-port defaults are flipped:

1. **Unit & protocol tests (CI-blocking):**
   - **Acyclic outer relay pinning & non-re-entrant send/recv (egress + ingress overflow):** Verify outer MASQUE relay connections reject virtual-route addresses and cannot migrate onto `SocketSlotId::VIRTUAL`; verify flooding a virtual route's bounded egress channel drops excess packets via `try_send` without blocking `MultiplexedUdpSocket::send()` or stalling the outer relay connection on the same `InnerEndpoint`; symmetrically verify flooding a virtual route's bounded ingress receive queue drops excess inner packets cleanly (`virtual_recv_queue_dropped` increments) without backpressuring the outer Tokio relay pump or stalling sibling virtual routes/control capsules.
   - **Multi-port `(remote_addr, local_slot)` affinity, anti-spoof & authenticated slot-mismatch:**
     - Client dials both `:443` (slot 0) and `:5483` (slot 1) on one `MultiplexedUdpSocket` from the **same** ephemeral source port; verify replies exit the exact local port dialed from the first Initial reply onward.
     - Spoofed unauthenticated UDP packets injected on the other port with the victim's `remote_addr` NEVER alter the established connection's `local_slot`.
     - **Authenticated slot-mismatch case:** An authenticated 1-RTT packet (valid DCID + valid AEAD tag) forwarded/replayed from `:443` (slot 0) onto `:5483` (slot 1) MUST NOT flip `self.path.local_slot` until RFC 9000 §8.2 `PATH_CHALLENGE`/`PATH_RESPONSE` succeeds on `(remote_addr, slot 1)`.
   - **Synthetic ULA prefix isolation & intake/emission filtering (`fd00:53a0:5251::/48`):** Physical socket `send()` rejects destinations matching `is_synthetic_virtual_ip`; physical `poll_recv()` drops and counts spoofed inbound packets sourced from the synthetic prefix; `ADD_ADDRESS`, `OBSERVED_ADDRESS`, `PUNCH_ME_NOW`, `CandidateDiscoveryManager`, `BootstrapCache`, `PeerHintRecord`, `manual_known_peer_udp_addrs`, OS interface enumeration, and mDNS all reject/strip synthetic ULA addresses on both intake and emission; `route_gen` increments on relay reconnect and drops stale-generation routes; `MAX_VIRTUAL_ROUTES` cap holds under churn.
   - **CID pool & 0-RTT compatibility (incl. rollback test):** `CidQueue::LEN == 16`, `LOC_CID_COUNT == 16`, `issue_cids_limit()` returns `16` for Wave-4 peers and `5` for simulated `0.30.0` peers (while Wave-4 receives `min(16, 8) = 8` CIDs from a `0.30.0` peer and caps outbound probe width dynamically to `rem_cids.spare_count()`); `validate_resumption_from` accepts `5 -> 16` and returns `TransportError::PROTOCOL_VIOLATION` on `16 -> 5` (and rejects `InConnectionMigrationV1` mismatches); an end-to-end `16 -> 5` 0-RTT rollback test verifies BOTH that (a) an unmitigated server accepting a pre-rollback ticket triggers client `TransportError::PROTOCOL_VIOLATION` (`src/connection/mod.rs:3244`) and (b) applying the required rollback step (`max_early_data_size = 0` or rotated/flushed server ticket key/session cache) rejects 0-RTT at TLS and falls back cleanly to 1-RTT; an `N = 8` spray uses 8 distinct unused DCIDs and retires unused probe CIDs on round completion.
   - **Per-path dynamic virtual MTU:** Connection starting on a 1,280 B outer MASQUE virtual path clamps 1-RTT to `<= 1,179 B` with 0% steady-state stream spill, reacts dynamically when outer `max_datagram_size()` shrinks to `1,050 B` mid-session, and unlocks full `1,200 -> 1,452 B` physical DPLPMTUD immediately upon migrating to a direct physical path.
   - **Client `0x50C6` off-path probe admission (`connection/mod.rs:1623`) & `server_config.migration` gate:** With `InConnectionMigrationV1 (0x50C6)` negotiated and `server_config.migration == true`, verify `Side::Client` admits authenticated `PATH_CHALLENGE`/`PATH_RESPONSE` from a server direct address in `probing_paths` (and seeds a bounded probe on authenticated `PATH_CHALLENGE`), while rejecting unvalidated non-probing packets from off-path addresses and rejecting ALL off-path server packets when `0x50C6` was not negotiated or `server_config.migration == false`.
   - **Non-disruptive speculative probing, client-initiated promotion, state rewrite & rollback:** During an `N = 8` probe round where all 8 direct candidates are blackholed, active streams on the MASQUE virtual path experience **0** interruptions and **0** dropped packets. When both ends spray probes and the server validates first, the server waits for client non-probing 1-RTT traffic (0 ping-pong); when the client promotes candidate #5, both sides converge onto the direct path with **0** new handshakes, **unchanged `PeerLifecycleEvent` / `TrackedConnection.generation`**, **0** `PeerLifecycleEvent::Replaced` events, **0** stream resets, **0** [ADR-017](ADR-017-single-arbiter-connection-retirement.md) retirement triggers, and verified in-place rewrites of `connected_peers`, `direct_path_statuses`, `connection_lifecycle` (`traversal_method`), and `successful_candidates`. When the promoted direct path is immediately blackholed before 1-RTT ACK, traffic falls back cleanly to `prev_path`.
   - **Mixed-version (`0.30.0` ↔ Wave 4) interop:** Without mutual `InConnectionMigrationV1 (0x50C6)`, relay-to-direct upgrade falls back cleanly to [ADR-020](ADR-020-hybrid-relay-session-negotiation.md) Decision 5 + [ADR-017](ADR-017-single-arbiter-connection-retirement.md) with zero protocol errors.
2. **Dedicated Wave 4 connection-lifecycle soak gate (required before flipping `auto_migrate` or P7 dual-port in production):**
